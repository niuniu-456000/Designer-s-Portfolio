# Enterprise Dashboard OS
# RULES.md
Version: 1.0

---

# Core Principle

Every visual decision must serve business understanding.

Every layout decision must improve operational efficiency.

Every component must have business meaning.

Decoration is never a goal.

Communication is the goal.

---

# Dashboard Identity

A dashboard is:

✔ Operational System

✔ Decision Support System

✔ Information Architecture

✔ Business Interface

A dashboard is NOT:

✘ Marketing Poster

✘ Landing Page

✘ Product Advertisement

✘ Cyberpunk HUD

✘ Sci-fi Movie Screen

---

# Business First

Never begin from UI.

Always begin from business.

Required order:

Business

↓

User

↓

Scenario

↓

Decision

↓

Information

↓

Layout

↓

Visual

---

# Information Hierarchy

Every dashboard must contain only ONE visual center.

Priority:

Level 1

System Hero

↓

Level 2

Critical KPI

↓

Level 3

Operational Modules

↓

Level 4

Supporting Information

↓

Level 5

Decorative Elements

Decorations can never compete with business information.

---

# System Hero Rules

Every dashboard must contain one System Hero.

The Hero represents:

System

Network

Platform

Business Core

Operation

Never:

Draw a beautiful illustration.

Draw a product rendering.

Draw a decorative 3D object.

Draw an oversized logo.

Hero must explain the business.

---

# Layout Rules

Use grid systems.

Prefer 8pt spacing.

Large negative space.

Strong alignment.

Balanced density.

Avoid visual chaos.

Modules should never touch each other.

---

# Grid Recommendation

Desktop Dashboard

1920 × 1080

Margins:

48px

Grid:

12 Columns

Gutter:

24px

Component Radius:

8px

Card Padding:

24px

Section Gap:

24~32px

---

# KPI Rules

KPI cards should contain:

Status

↓

Label

↓

Primary Value

↓

Trend

↓

Comparison

Never place numbers without labels.

Never place labels without context.

---

# Chart Rules

Every chart answers one question.

Do not build charts for decoration.

Every chart needs:

Title

Unit

Legend

Scale

Meaning

Avoid:

3D Charts

Exploded Pie Charts

Rainbow Colors

Heavy Animation

---

# Color Rules

Color represents business status.

Not decoration.

Recommended Semantic Colors:

Normal

Green

Information

Cyan

Warning

Amber

Critical

Red

Background

Deep Navy

Never use random colors.

---

# Typography Rules

Typography is hierarchy.

Use only three levels.

Level 1

Dashboard Title

32~40px

Level 2

Section Title

18~22px

Level 3

Body

12~14px

Numbers

Large

Bold

Readable

Never use excessive font sizes.

---

# Icon Rules

Icons communicate meaning.

Icons are functional.

Do not decorate with icons.

One icon

↓

One meaning

---

# Motion Rules

Motion must explain change.

Motion must never distract.

Recommended:

Fade

Slide

Scale

Counter Animation

Avoid:

Continuous Rotation

Random Floating

Heavy Particle Effects

---

# Component Rules

Every component must be reusable.

Every card must support the business.

Every chart must support decisions.

No isolated decorative modules.

---

# White Space Rules

Whitespace is information.

Do not fill every space.

Leave breathing room.

Hero should always have space around it.

---

# Visual Balance

Avoid left-heavy layouts.

Avoid right-heavy layouts.

Avoid equal visual weight everywhere.

Create one visual center.

Everything else supports it.

---

# Dashboard Grammar

Business

↓

Hero

↓

KPI

↓

Analysis

↓

Decision

↓

Action

Never reverse this order.

Enterprise

Avoid:

Cyberpunk

---

# Implementation Rules

If a React project exists:

Always modify the existing React application.

Prefer:

src/App.tsx

src/components/

src/index.css

Never replace the project with static HTML.

Never stop after planning.

Always implement.

---

# Build Rules

Do not install packages unless requested.

Use existing dependencies.

Prefer:

React

CSS

SVG

Native Components

Project must compile.

---

# Quality Checklist

Before finishing:

□ Business Mapping complete

□ Hero exists

□ Information hierarchy correct

□ Dashboard Grammar complete

□ Components reusable

□ Visual hierarchy correct

□ Typography consistent

□ Colors semantic

□ Build successful

□ No placeholder modules

□ No decorative fake widgets

---

# Golden Rule

If a visual element cannot explain business,

remove it.

If a component cannot support decisions,

remove it.

If an animation cannot communicate information,

remove it.

Everything must exist for a reason.
